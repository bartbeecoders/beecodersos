## Agent summary
BeeShell now has a `calc EXPR` command, and `make check` passes: 11 boot tests passed, 0 failed (16 self-tests, all scenarios, and the BIOS and UEFI ISO boots), and the BeeFS, beehive and evolve unit tests all passed.

**What I changed** (about 175 lines; nothing committed, `BUILD_NUMBER`/`OS_VERSION` and the protected files untouched, no new crates):
- **`kernel/src/shell.rs`**:
  - Added a small `calc()` evaluator for `+ - * / %`, parentheses and unary minus, with normal precedence.
  - All maths uses i64 checked operations, so division by zero prints `calc: division by zero` and overflow prints `calc: overflow` instead of crashing the kernel.
  - Bad input prints `calc: parse error` (or `calc: missing ')'`), and `calc` on its own prints a usage line.
  - `-7 / 2` gives `-3` and `-7 % 3` gives `-1` (results truncate toward zero); this is documented on the function.
  - Nesting is capped at 64 levels, so input like a thousand `(` returns an error instead of running out of kernel stack.
  - A negative literal can reach the smallest i64 value, `-9223372036854775808`.
- **Command wiring**: `calc` is in the `execute` match and in `COMMANDS` as `calc EXPR`, so `help` lists it.
- **`README.md`**: added `calc` to the command list.

**Tests added**
- **Self-test** `shell: calc expressions` in `kernel/src/selftest.rs`: precedence, parentheses, spacing, unary minus, truncation toward zero, smallest i64, division and remainder by zero, overflow cases (add, multiply, oversized literal, smallest i64 divided by -1, negating it), parse errors, and the deep-nesting limit.
- **Scenario** `tests/scenarios/calc.scn`: runs `calc 2 + 3` → `5` in the shell, plus every other example from the acceptance criteria, the `help` listing, and a final `calc` to show the shell still works after the error cases.
