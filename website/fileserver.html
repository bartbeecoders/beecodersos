Guide

Use it as a file server.

One folder of the machine, read and written by programs on your network: over plain HTTP for scripts, and over the S3 protocol for everything that already speaks it. Off until you switch it on, and nothing happens without the key. Everything on this page was tried on the HP that runs BeeCodersOs.

Switch it on

bee:/$ fileserver on
file server on, port 9000 (saved): it shares /share
key: qBfnHi6dXvegB9EvDjDC8ihn4rpb5Am9GQ3abwEW
with the key, a program can read, write and delete the files there; the link is not encrypted
fileserver on [PORT]
start it (port 9000 unless given); it is back after a restart
fileserver off
stop it: the machine listens on that port no more
fileserver
is it on, where, and how many requests came without the right key
fileserver key
show the key the OS made up (40 characters)
fileserver key new
another key: the old one, and every link, stops working at once
fileserver folder DIR
share another folder (never / or anything in /system)

From a script: plain HTTP

Every request carries the key. Folders answer with a listing in JSON; errors are JSON too.

KEY=qBfnHi6dXvegB9EvDjDC8ihn4rpb5Am9GQ3abwEW
BEE=http://192.168.0.40:9000

# what is there
curl -H "Authorization: Bearer $KEY" $BEE/api/files/
{"path":"/","entries":[{"name":"pictures","type":"folder","size":0}]}

# send a file (the folders above it are made), fetch it, delete it
curl -H "Authorization: Bearer $KEY" -T photo.jpg $BEE/api/files/pictures/photo.jpg
curl -H "Authorization: Bearer $KEY" -O $BEE/api/files/pictures/photo.jpg
curl -H "Authorization: Bearer $KEY" -X DELETE $BEE/api/files/pictures/photo.jpg
GET /api/files/PATH
a file's bytes, or a folder's listing; Range gives a part of a file
HEAD /api/files/PATH
the same, without the bytes
PUT /api/files/PATH
write the file; a PATH that ends in / makes a folder
DELETE /api/files/PATH
remove the file, or the empty folder

From an S3 client

The folders in the shared folder are the buckets, the files below them the objects: the same files the HTTP interface and the OS's own terminal see.

endpoint
http://ADDRESS:9000, path style, any region
access key id
beecoders
secret access key
the key (fileserver key)
what works
buckets; put, get, head, delete, delete many; listings with prefix, delimiter and pages; uploads in parts; ranges; presigned links
import boto3
from botocore.config import Config

s3 = boto3.client("s3", endpoint_url="http://192.168.0.40:9000", region_name="us-east-1",
                  aws_access_key_id="beecoders", aws_secret_access_key=KEY,
                  config=Config(s3={"addressing_style": "path"}))

s3.create_bucket(Bucket="photos")
s3.upload_file("holiday.mp4", "photos", "2026/holiday.mp4")      # in parts, by itself
s3.download_file("photos", "2026/holiday.mp4", "back.mp4")      # in ranges, by itself
print([o["Key"] for o in s3.list_objects_v2(Bucket="photos", Prefix="2026/")["Contents"]])

Requests are signed the way Amazon's clients sign them (AWS Signature Version 4). The OS works out every signature itself and compares all of it before it touches the disk; an upload is checked against the hash the client signed, or piece by piece, and gets its name only when all of it was right.

A link for one file

bee:/$ fileserver link /share/photos/cat.jpg
http://192.168.0.40:9000/photos/cat.jpg?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=…&X-Amz-Signature=…
anyone on the network with this link can fetch the file for 24 hours; 'fileserver key new' ends every link

The link opens in any browser, without the key, until it expires: 24 hours unless you say otherwise (fileserver link FILE 1 for one hour, a week at most). It fetches that one file and nothing else; change a letter of it and it fetches nothing.

Good to know

How large
a file as large as the disk has room, about 1 GiB at most; files go to and from the disk in pieces, never through memory whole
How fast
100 MB reaches the HP in 10 to 16 seconds and comes back in 9 to 12
Names
26 characters between the /, 16 folders deep (the file system's limits)
Not encrypted
the key and the files cross the network as they are: for your own network, not the internet
One folder
no request can leave the shared folder, whatever its path says
Not there
copies between objects, versions, access lists and tags; times of change (the file system keeps none)
