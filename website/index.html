An operating system that helps improve itself.

BeeCodersOs records what goes wrong and what people miss. An AI turns that into small, tested changes that a person approves. Every new kernel is tried in a spare slot on the real machine and rolled back automatically if it fails.

The improvement loop

Most systems get better when someone files a bug. BeeCodersOs notices for itself, and every step is small enough to check and to undo.

  1. 1

    It observes

    Crashes, commands that don't exist, failed commands and wishes are recorded on the machine — command names only, never what you typed after them.

  2. 2

    It collects

    beehive, a small daemon on a host computer, gathers those signals from every machine and turns them into a backlog.

  3. 3

    An AI proposes

    A coding agent takes one backlog item, writes the change and a test for it, and must pass the whole test suite.

  4. 4

    A person approves

    Nothing lands on its own: a human reviews the change before it is merged.

  5. 5

    It tries, safely

    The new kernel goes into the spare of two boot slots and boots on trial. If it doesn't pass its health check, the machine goes back to the old one by itself.

What it can do today

Talk to it

ask answers questions about the system, explain explains the last error or crash, and do turns a task in plain words into shell commands that run only after you agree. Some commands a plan may never run, whatever you answer.

A desktop

Windows you can drag, a mouse, buttons to start programs, several terminals side by side, a text editor and a file manager — drawn by all processors at once.

A web browser

browse shows web pages as clean text: headings, lists, links you follow with Tab or a click. Type words instead of an address to search the web.

Its own network stack

Ethernet drivers, ARP, IPv4, DHCP, DNS, TCP, HTTP, time and file transfer — written from scratch, every received byte treated as untrusted.

Its own file system

BeeFS, on RAM, IDE or SATA disks; an installer that puts the OS on a disk, and A/B kernel slots for updates over the network.

Every core

All processors start at boot. Work is split into pieces that run on every core: hashing 64 MiB takes 130 ms instead of 521 ms on a four-core machine.

Careful by design

  • Tests before anything ships. One command, make check, boots the system dozens of times in virtual machines — BIOS and UEFI, disks, network, desktop, crashes and rollbacks — with no internet and no AI needed.
  • Privacy. The event log keeps command names, never their arguments. Host names and addresses are never logged. API keys live on the host, never on the machine.
  • An off switch. ai off stops every AI feature, and the system works fine without it.
  • Closed by default. The machine listens on the network only for a service you switched on yourself.
